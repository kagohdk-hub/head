### 問いかけ
行動管理というか目標管理というかの話。
現状と今取り組んでいる領域と、取り組みが達成されたら到達できる場所と、最終的に到達したい場所があるイメージで
current - wip - target - goal みたいな感じ？
で、
例えば、カレーを作れるというステータスは、調理器具がある、と　材料がある　というステータスを前提に取り、カレーを食べられる　というステータスは　カレーを作れるというステータスを前提に取るが、カレーを作れるというステータスがなくても、カレー屋さんにいけるというステータスがあればいい
みたいな、これをネットワーク図的に表記し、今はここの部分を取り組んでるんだということを見た目でぱっと見えるようにする
そういうことができたらいいなと思いつつ、
何かアイディアある？
できればただの画像よりはインタラクティブな感じで動かしたいが、ぬるぬる動くようにするとメモリをものすごく食うのはp5.jsで体感済み
### 回答
いいですね、これは「予測」フレームワークや詰将棋的な前向きシミュレーションの発想とも相性が良さそうです。ネットワーク図でAND/OR前提条件を表現して、現在地から目標までの経路を可視化する、というのは筋が良いと思います。

設計方針を先に整理します。

**データモデル**
- ノード = ステータス(状態)。`id`, `label`, `status`(locked/target/wip/achieved), `isGoal`(最終到達点フラグ)
- 依存関係はノード自身が持つ「要件」として表現: `requires: [[A,B],[C]]` のように **外側配列=OR、内側配列=AND**。カレー例なら「食べられる」の要件は `[["作れる"],["カレー屋に行ける"]]`

**レイアウト**
- p5.jsのような力学シミュレーション(継続的な物理演算)は使わず、**一度だけ計算する階層レイアウト**(トポロジカルソート→層分け→簡易バリセンター法で交差低減)。CPU/メモリ負荷はほぼゼロで、静止画的に軽い。
- 下から上へ「現状→目標」の積み上げ方向。詰将棋の一手先読みのような、下から候補手を積んで最終形に至るイメージに寄せました。

**インタラクション**
- ノードをクリック→選択し、そのノードに至る依存チェーン(祖先)と、そこから開けるチェーン(子孫)をハイライト、他は減光
- サイドパネルでステータス変更(locked/target/wip/achieved)とゴールフラグの切り替え
- JSON直接編集モードあり(gitで管理しやすいテキストベース)
- `window.storage` で状態を保存(ブラウザ内、あなた個人のみ)

作ってみます。**設計のポイント:**

- **データ構造**: `requires: [[A,B],[C]]` — 外側配列がOR、内側がAND。カレー例そのままデフォルトで入れてあります(材料+調理器具→作れる、AND / 作れる or カレー屋に行ける→食べられる、OR)
- **レイアウトは静的計算のみ**: p5.jsの力学シミュレーションと違い、トポロジカルソート→層分け→バリセンター法(交差低減)を初回に1回だけ計算し、あとはCSS transformでパン/ズームするだけなので継続的な演算コストがゼロです
- **見た目でぱっと分かる**: 未着手(グレー)→到達できる(青)→取り組み中(黄、塗りつぶし)→到達済み(緑、塗りつぶし)。最終ゴールは点線リングで別枠表示
- **クリックで依存チェーンを追跡**: ノード選択で祖先(前提条件)と子孫(そこから開ける場所)だけを明るく残し、他は減光
- **`window.storage`で永続化**: 編集内容はブラウザに自動保存され、次に開いても状態が残ります
- **JSON直接編集**: gitで管理しやすいようテキストベースで全データを編集可能

試しに「カレーを作れる」ノードをクリックしてみてください。前提条件と、そこから開ける先が両方パネルに出ます。

いくつか気になっている点:
- 現状はステータス変更が手動(前提条件が未達成でも「到達済み」にできてしまう)ですが、これは意図的です。実際の進捗は現実の方が先行することも多いので、厳密なバリデーションより自己申告ベースの方が使いやすいかと思いました
- レイヤー配置は「最も遠い経路」基準(OR分岐があっても保守的に深い方の層に配置)にしています。最短経路基準にすると視覚的にDAGの上下関係が崩れることがあったので

実際の目標(仕事の話や協会の話など)を入れ始めると、ノード数が増えて layerGap や nodeGap の調整が要るかもしれません。使ってみて詰まった箇所があれば教えてください。
